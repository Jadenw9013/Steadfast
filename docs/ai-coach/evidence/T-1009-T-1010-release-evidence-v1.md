## Engineering assertions

- The corpus covers prompt injection, authority escalation, tool/browser requests, cross-tenant requests, invented catalog and clarification IDs, invented numeric facts, invalid transport/output schemas, provider caution, transient retry, timeout, and token ceiling behavior.
- Provider measurements contain only operation/contract identifiers and numeric attempt, latency, retry-delay, and token counts. They contain no prompt text, client ID, provider trace, raw error, model prose, intake, or health answer.
- Monitoring groups provider faults by boundary outcome and failure code and exposes only aggregate numeric measurements. Tests reject prompt, trace, intake, safety-answer, and client-identifier leakage.
- Every operational scope (`GENERATION`, `PROVIDER`, `FINALIZATION`, `ACCEPTANCE`, and `ARTIFACT_PUBLICATION`) has a revision-bound disable and restore drill. A stale rollback is rejected and remains fail-closed. Operational audit updates are rejected by PostgreSQL.
- A governed artifact revocation still disables generation, provider, finalization, and acceptance together. Acceptance and finalization continue to re-run the deterministic gate and bind the exact synthetic account, candidate, artifacts, evidence, and revision tuple.
- The iOS validator always parses the AI Coach Swift sources. With full Xcode it additionally requires an available iOS Simulator and runs the full `steadyfastTests` target; CI invokes it with `--require-xcode`, so a missing Xcode/simulator is a failure rather than a silent skip.

No pass/fail alert threshold, latency SLO, token budget for live service, cost estimate, or retry schedule is approved by this evidence. The hooks measure these values so qualified operational and provider reviewers can approve versioned limits later.
